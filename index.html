How Rimsha adds a product

How Rimsha adds a product

Recipes today are added from a front-end page, not from WordPress admin. Rimsha goes to mybodybella.com/my-recipes/, enters the passphrase once, pastes the recipe (and an optional photo), clicks Check this recipe, then Add it to my website. Categories are assigned automatically from the name and ingredients. The public library is at mybodybella.com/recipe-library/.

This Products page should work the same way for Rimsha: a front-end screen she already knows how to use, not wp-admin.

Proposed steps

These steps assume a new Products admin page, built like /my-recipes/, for example /my-products/, using the same passphrase. That page does not exist yet. This is the recommended approach, not something already live.

  1. Go to the Products admin page (proposed: mybodybella.com/my-products/).
  2. Enter the passphrase if this device has not already been remembered.
  3. Fill in the product fields listed below.
  4. Click a review button, check that the name, description, photo, link, and category look right. Nothing has been added to the website yet.
  5. Click add. The product appears on the Products page, the same way a recipe appears in the library after it is added.

Fields a product entry needs

  • Photo. Optional, same as recipes. Any photo from a phone or computer, resized automatically.
  • Name. Required. This is the title on the card.
  • Short description. A few sentences for the card. Required.
  • Link. The URL the "View product" button opens. Required, because product cards link out instead of opening a recipe-style detail page.
  • Category. Rimsha picks one. Recipe categories are assigned automatically from ingredients. Products do not have that, so the category has to be chosen.

Editing later

Under the form, a list of every product, each with View, Edit, and Remove, the same as the recipe list on /my-recipes/.

What is an assumption. The recipe system is a custom WordPress plugin with its own post type, a hidden library page, and the /my-recipes/ paste screen. Products would follow that pattern: a sibling post type and a sibling admin page, plus a Products index page built like /recipe-library/. Products would use a short form rather than the recipe paste parser, because a product is a photo, name, description, link, and category, not a block of recipe text.
